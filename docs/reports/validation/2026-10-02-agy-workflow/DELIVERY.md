## 要点

- **已经落地到真实安装环境。** 新建/导入 Agent、后台服务、网络准备、角色输入、完整问答、文件产出、验收和关联继续已打通。用户通常只需名称、工作目录、职责，不必先理解 Fleet、YAML 或 tmux。
- **主要断点来自模块衔接。** 本轮实际修复排队取消不收口、角色未注入、活动取消状态不准确、新代网络恢复卡住、过期运行只能重启 daemon 才恢复，以及实际历史库网页首连问题。保留原有 Task/Run/Journal 与事务基础，没有另造一套平台。
- **用真实执行证明。** 正式 `agy-graft` 执行、文件精确字节/哈希、Task/Run/Journal、浏览器与80×24 PTY、systemd PID/进程树和安装工件都已取证；完整主链的取消进程树约4秒停止，系统服务崩溃约32.7秒自动收口为不确定，95秒工具工作跨多个续租周期，未重复执行原任务。
- **失败也保留。** 产品缺陷、夹具断言错误和修复后复验分别记录；D、R、I分开，不能把局部检查或mock写成真实AGY通过，也不报虚假的“22组全部通过”。
- **参考项目只取小机制。** 采用连贯的结果/继续入口、稳定领域身份、每Run冻结角色与工作目录、明确停止回执及可恢复工作记录。暂不扩跨领域平台、组织治理或新Runtime；WorkBuddy/CodeBuddy保留，未做本轮专项覆盖。

## 现在如何用

```sh
openagentx agent add
openagentx agent status
openagentx agent open <agent-id>
```

工作台：[http://127.0.0.1:18100](http://127.0.0.1:18100)。演示Agent `agy-onboarding-e2e` 当前在线、无活动任务，可直接打开查看[真实生成并继续修改的报告](evidence/installed-browser-9434479-daily01/continued-workflow-review.md)及任务记录；实际工作请另外添加Agent和目录。`OAX:overview` 已显示实际Agent状态、最近结果和打开/恢复入口。已有Agent使用 `agent resume <agent-id>` 恢复后台；终端用户使用 `agent open <agent-id> --console`。

先发“问答”读取材料，再用“执行任务”生成专用产物。检查文件后接受结果；追加修改点“继续此工作”。执行中补充安排到下一Run，取消表示停止后续执行，已经写出的文件不会自动撤销。任务业务效果未由系统独立核验时保留原记录，用户验收另行留痕。

## 已知边界

当前定位是本机单用户AGY工作流。默认AGY不提供可发起的原生审批/preflight入口；命名网络配置恢复仍需工作台明确测试发布。绕过systemd直接强杀Worker时，账本会自动收口，但遗留子进程需自行确认；正常受管service的进程组清理已实测。更长时程、复杂并发、多用户、错代理组合和完整视觉体验优化不以本轮证据一概宣称通过。Web本地文件预览/下载尚未统一，模型回复中的file链接可能无法打开，应按实际工作目录读取产物；已接受任务的列表仍显示原uncertain状态，验收结论在详情中。
