12: Your agent history is scattered across `~/.claude`, `~/.codex`, and a dozen other private directories. Wake reads them all, read-only, and gives you one fast window into it. Everything stays local; Wake only contacts GitHub when you explicitly check for an update.
13: 
14: ![Wake — sessions list and transcript view](imgs/screenshot-1.webp)
15: 
16: ## Features
17: 
18: - **Unified browsing** — all sessions grouped by agent / project, with Grok Build subagents nested under their parent and live file watching for incremental updates
19: - **Full-text search** (⌘K / Ctrl+K) — SQLite FTS5 trigram index; handles CJK text and code substrings (like `useEffect(`) equally well; jumps straight to the matched message in the transcript
20: - **Transcript view** — per-message rendering with user/assistant bubbles, inline images (copy or save them), collapsible tool-call clusters, thinking summaries, tree-sitter code highlighting (30+ languages)
21: - **One-click resume** — reopens the session in your terminal (Terminal/iTerm on macOS; native terminal hosts on Linux and Windows) at the original project directory (`claude --resume`, `codex resume`, …)
22: - **Manage** — star/pin (stored in Wake's own DB, original files untouched), export to Markdown or save an inline image through the system Save dialog (Wake remembers the last folder), delete (system Trash + tombstone so deleted sessions stay deleted)
23: - **Insights** — a stats page for your whole library: GitHub-style activity heatmap with streaks, hour / weekday / month breakdowns, and Agents / Projects / Models leaderboards switchable between sessions, tokens, and prompts
24: - **Remote hosts** — mirror the sessions on your other machines over SSH (Settings → Remote hosts); they show up next to local ones with an `@host` badge, searchable like everything else, and resume through a copied `ssh -t` command
25: - **Connect your agents (MCP)** — a bundled read-only MCP server, `wake-mcp`, lets Claude Code, Codex, Cursor or any MCP client search your whole history, list recent sessions per project and read transcripts page by page, so a new agent can pick up where another one left off; Settings → Connect has copy-paste setup snippets
26: - **Command line** — `wake-cli` gives the same answers to anything that can run a shell command: `wake-cli sessions --project "$PWD"`, `wake-cli search "…"`, `wake-cli show <key>`; it prints the same text an MCP client sees; `npx skills add iAmCorey/Wake` installs a skill so agents reach for it on their own; `wake-cli refresh` keeps the index fresh from a scheduled task while the app is closed

141: ## Privacy stance
142: 
143: - Agent data directories are opened **read-only**; Wake never writes to another tool's files or databases
144: - Credential files (`auth.json` and friends) are never read
145: - Remote hosts are mirrored read-only with `rsync` over your existing SSH setup: only session data and its sidecar files come across (never credentials), nothing on the remote machine is ever written, and the mirror lives inside Wake's own data directory (`remotes/<host>/`), so removing the host removes it
146: - No background network requests — the only network actions are a user-initiated update check against Wake's public GitHub Release metadata and, if you configure remote hosts, SSH/rsync to those hosts on launch, refresh, and Sync now; session data is never sent anywhere else
147: - Wake's own index lives at `~/Library/Application Support/wake/wake.db` (Linux: `~/.local/share/wake`, Windows: `%LOCALAPPDATA%\wake`) and can be rebuilt from scratch at any time (stars/pins live in a separate table and survive rebuilds). Three small preference files (`appearance`, `language`, `window.json`) sit beside it on macOS, under `~/.config/wake` on Linux and `%APPDATA%\wake` on Windows; Open In and export-folder choices live in the index database's `prefs` table
148: 
149: ## Performance
150: 
151: On the author's machine (~310 sessions, ~800 MB of JSONL): full index ~5 s, subsequent launches are instant (mtime-based incremental scan), search results in under 1 ms.

153: ## Install
154: 
155: Download `Wake-<version>-macos.zip` from the [latest release](https://github.com/iAmCorey/Wake/releases/latest), unzip, and drag Wake to Applications. The release is a Universal Binary for both Apple Silicon and Intel Macs. Or build from source (requires a Rust toolchain):
156: 
157: ```bash
158: git clone https://github.com/iAmCorey/Wake && cd Wake
159: scripts/make-app.sh          # builds dist/Wake.app (icon + Info.plist, ad-hoc signed)
160: open dist/Wake.app
161: ```
162: 
163: To build the same Universal Binary locally, install the `aarch64-apple-darwin` and `x86_64-apple-darwin` Rust targets, then run `scripts/make-app.sh --universal`.
164: 
165: The app is ad-hoc signed, so if you download a prebuilt copy instead of building it yourself, macOS Gatekeeper will block the first launch — right-click the app and choose *Open*, or run `xattr -d com.apple.quarantine Wake.app`.

139: pub fn build_index(path: &Path, events: &dyn ScanEvents) -> Result<Outcome> {
140:     if path.exists() {
141:         return Ok(Outcome::Skipped(Skip::Exists));
142:     }
143:     let _lock = match IndexLock::try_acquire(path, "wake-cli index")? {
144:         Ownership::Ours(lock) => lock,
145:         Ownership::Held(holder) => return Ok(Outcome::Busy(holder)),
146:     };
147:     // 锁外那一眼可能过时:GUI 刚建完库又退出了
148:     if path.exists() {
149:         return Ok(Outcome::Skipped(Skip::Exists));
150:     }
151:     let staging = Staging::new(path);
152:     let tally = {
153:         let store = Arc::new(Store::open(&staging.0)?);
154:         scan_with(&store, events, true)?
155:     }; // 关掉最后一个连接即 checkpoint,-wal/-shm 消失,临时库自成一体
156:     match std::fs::hard_link(&staging.0, path) {
157:         Ok(()) => {}
158:         // 有人抢先了(不认锁的老版本 GUI 首扫)。他的库归他,退让
159:         Err(e) if e.kind() == std::io::ErrorKind::AlreadyExists => {
160:             return Ok(Outcome::Skipped(Skip::Exists))
161:         }
162:         // 个别文件系统不给硬链接:退回 rename,但只在目标确实还空着时
163:         Err(_) if !path.exists() => std::fs::rename(&staging.0, path)?,
164:         Err(_) => return Ok(Outcome::Skipped(Skip::Exists)),
165:     }
166:     for suffix in ["-wal", "-shm"] {
167:         let _ = std::fs::remove_file(format!("{}{suffix}", path.display()));
168:     }
169:     Ok(Outcome::Done(tally))
170: }
