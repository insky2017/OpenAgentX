# Orca 对照研究

## 结论

- **Orca 的主要参考价值是围绕一项开发工作组织操作。** 工作区、Agent、代码差异、审阅和继续入口相互连接；这适合帮助 OpenAgentX 缩短“任务发出后去哪里看、看完如何继续”的路径。本批未运行桌面，不能据源码判定实际体验更流畅。
- **它也有真实的持久编排机制。** 固定版本包含 SQLite Run / Task / Dispatch、消息交付、能力凭据和持久幂等回执，文档将结构化编排列为实验能力。不能因为它有终端界面，就把这些机制当成没有实现。
- **最值得参考的是如实表达执行证据。** `finished_unverified`、已接收的 Worker 回报、进程存活与停止确认分别记录；失联不直接变成已停止。但 Worker 自报成功仍不能代替 OpenAgentX 对实际业务效果的核验。
- **它对复杂度的警示也很直接。** PTY / 结构化会话、桌面 / 无头、SSH / 配对远端、移动端与状态兼容共同增加维护面。借鉴应落到现有 A/B/C 的小结果，保留 OpenAgentX 已有事务、Mailbox、Journal、lease/fencing。
- **不迁入默认权限放宽和整套 IDE 技术栈。** 固定代码的新建 TUI 默认参数沿用 YOLO 映射，用户可选择 Manual；这是与 OpenAgentX 不同的权限取舍，不应随 UI 方案一起带入。

## 对现有改进顺序的补充

| 原批次 | Orca 提供的参考 | OpenAgentX 的最小落点与验收 |
|---|---|---|
| A：可靠撤回与当前结果 | 区分停止请求、进程动作、已确认退出和未知；按确切 Dispatch 归属结果 | 修已有取消事务及最新 Run 投影。未领取取消后不再执行；活动取消失联不误报完成；最新回复与历史可区分，随后仍可执行下一项 |
| B：真正完成与继续 | Worker 回报归属、幂等回执、事实来源和失去回执后的明确恢复动作 | 对齐 ADR-006 的 query / mutation（有副作用任务）与现有 SessionBinding。真实角色输入、回复/文件结果、Task / Run / Journal 和续问均可核对；重试确认回报不变成重复执行副作用 |
| C：首次使用与恢复 | 从任务直接到负责它的执行界面；跨入口状态来源明确，陈旧与未知有解释 | 用现有 API 支持 overview 的就绪、待处理、最近结果和下一步。初连失败恢复后重取权威状态，80×24 / 390px 可到结果，操作不要求理解内部模块 |

以上是后续实施建议，不是本批已交付能力。Orca 的源代码与测试选例补充现有验收，不要求增加一套 Task / Dispatch 模型；其状态统一仍有已落地与过渡适配之分，不能把文档中后续计划算成完成。
