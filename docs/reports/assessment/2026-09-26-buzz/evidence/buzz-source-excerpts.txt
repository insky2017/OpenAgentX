427:         // with process_group(0), so its PID == its PGID. Killing the group

438:         }

444:             Ok(Err(e)) => tracing::debug!("child wait error after kill: {e}"),

28: 
29: Buzz is a self-hostable workspace where humans and AI agents share the same rooms.
30: 
31: A Buzz **community** is the workspace a user reaches by URL. In the single-relay
32: setup that ships today, the relay URL selects exactly one community. A hosted
33: operator can serve many communities behind many domains or subdomains, but the
34: client-facing rule stays the same: the URL is authoritative for the workspace,
35: and all tenant-observable state under that URL is community-local.
36:

38: 
39: In practice it feels like a team workspace. Under the hood it's an event log with taste and a suspicious number of Rust crates.
40:

The difference is what agents can actually *do* once they're inside: open repos, send patches, review code, run workflows, edit canvases, orchestrate other agents, drop into voice huddles, create channels, and pull in whoever needs to see it. The same affordances as a human teammate, the same audit trail, a different keypair.

61: /// Bind a raw connection host to a [`TenantContext`], failing closed.
62: ///
63: /// This is the single row-zero entry point. It normalizes the host with the
64: /// one shared rule, resolves it, and on any non-success (unmapped *or* lookup
65: /// error) returns a [`BindError`] the caller turns into a generic rejection.
66: /// There is deliberately no path that yields a default or fallback community.
67: ///
68: /// The returned [`TenantContext`] carries the *normalized* host, so downstream
69: /// NIP-05 / audit labelling and the NIP-98 `u`-host check all see the same
70: /// canonical form the community was resolved from.
71: pub async fn bind_community<R: HostResolver>(
72:     resolver: &R,
73:     raw_host: &str,
74: ) -> Result<TenantContext, BindError<R::Error>> {
75:     let host = normalize_host(raw_host);
76:     // Inv_RowZero (host-binding seam): an empty raw_host carries no community
77:     // evidence — there is no `connection.host` to resolve, so no community can
78:     // be derived from it. Fail closed BEFORE the resolver lookup. The schema
79:     // does not forbid an `host = ''` row in `communities`, so without this
80:     // guard a request with a missing/whitespace-only Host header would silently
81:     // bind to a misconfigured empty-host community. Reuse `UnmappedHost` (not a
82:     // distinct variant) so the rejection is byte-identical to any other unmapped
83:     // host — an unauthenticated caller cannot probe for an empty-host row.
84:     if host.is_empty() {
85:         return Err(BindError::UnmappedHost);
86:     }
87:     match resolver.resolve_host(&host).await {
88:         Ok(Some(community)) => Ok(TenantContext::resolved(community, host)),
89:         Ok(None) => Err(BindError::UnmappedHost),
90:         Err(e) => Err(BindError::Lookup(e)),
91:     }

1: # Agent profile identity
2: 
3: ## An explicit key is exact
4: 
5: Opening a public key from a message, member, DM, deep link, or Instances row
6: always opens that identity. Active, stopped, archived, and relay-only keys obey
7: the same rule. A local managed record may supply controls only for that exact
8: key. An owner-signed kind 30177 `persona_id` (or an archive request's historical
9: persona link) is **not** an identity alias and does not grant access to a local
10: sibling's controls, definition, configuration, or Start action.
11: 
12: Only explicit persona navigation (for example, the persona card in My Agents)
13: selects an archive-aware representative using `pickProfileAgent`. With no live
14: representative, it remains a persona-only surface and may offer Start. An
15: explicit relay-only key must not turn into that persona-only surface, even if a
16: matching definition exists locally. There is no synthetic/secretless
17: `ManagedAgent` record.
18: 
19: This intentionally supersedes the old historical-message redirect: a message
20: from stopped A no longer opens running B merely because they share persona P.
21: The requested key takes precedence even if the caller also supplies persona
22: context. Local instance profiles may still show their own linked definition and
23: an explicitly navigable Instances list. Ownership alone permits owner-scoped
24: relay reads, not local management.
25: 
26: Implementation: `useCanonicalManagedAgentProfile` and `UserProfilePanel`.
27: The obsolete historical-persona relay lookup and inactive-instance redirect
28: helper have been removed instead of adding another exception flag.
29:

33:   active/stopped/archived/relay-only keys, and persona representative selection.
34: - `profile/lib/useCanonicalManagedAgentProfile.test.mjs`: remote A cannot borrow
35:   persona P/local B, including persona-only navigation and returning to A.
36: - `tests/e2e/exact-key-profile.spec.ts`: relay-only profile controls versus
37:   explicit persona navigation, with and without a local sibling; exact archived

47: ## Honest Costs
48: 
49: **You bring the substrate.** A provider makes deployment one press, not free. The cluster, the credentials, the image policy are yours to run — same deal as the sovereign relay ([VISION_SOVEREIGN.md](VISION_SOVEREIGN.md)): ownership is work.
50: 
51: **Handing over the key is a decision.** Deploying remotely means trusting the provider binary and the substrate it targets with the agent's identity key. On Kubernetes, that key rests as a Secret: anyone the cluster trusts to read secrets in that namespace can read it. The design narrows the blast radius — immutable per-attempt secrets, no service-account token, digest-pinned images — rather than implying an isolation it doesn't provide.
52: 
53: **No backchannel cuts both ways.** The desktop shows you presence and words, not CPU graphs — and it holds no guaranteed emergency kill switch into the substrate. Stopping a healthy agent is a message; dealing with an unhealthy one, and all deep diagnostics, live in the substrate's own tools, where they always did.
54: 
55: **Self-reaping needs a living reaper.** The inactivity timer runs inside the body it exists to end — a body wedged badly enough to stop running its own timer cannot finish itself, and the desktop will not do it for it. That failure belongs to the substrate: a namespace TTL policy is the backstop, not an afterthought.
56: 
57: **The body's state is mortal.** Files, checkouts, half-finished working trees — gone with the body unless the substrate persists them. The agent survives; its scratch space doesn't. Durable knowledge belongs on the relay, and agents are built to put it there.
58: 
59: **Presence can lag the truth, but not for long.** If the substrate kills a body without ceremony, the presence dot can outlive the agent — by seconds if the connection drops cleanly, by at most about three minutes if it doesn't. Presence is a lease the agent renews, not a flag it sets: a dead agent stops renewing and the relay forgets it. A bounded wrong dot, never an indefinite one.
60: 
61: **A running agent finishes on the configuration it started with.** New keys, new models, new settings take effect on the next body. And an instance that never got far enough to run — a body that failed to start — is the substrate operator's residue to clear, with the substrate's own tools. Editing an agent mid-sentence was never on the menu.
62: 
63: These are honest costs. They're worth it if you want agents that outlive your laptop, on infrastructure you already trust, with no new control plane to guard. Know which one you are.

[remote-contract] VISION_REMOTE_AGENTS.md:19-45
19: ## The Only Tether
20: 
21: Remote-execution systems accumulate control planes. An agent runner, a status poller, a log shipper, a kill switch — each one a live connection into your infrastructure, each one a credential that can leak, each one a thing that must be rebuilt for every new substrate.
22: 
23: Buzz's answer is an axiom: **after deploy, the desktop retains no substrate control channel.** Launch is a single one-way handoff — the desktop resolves the provider through one narrow path, stages one exact artifact for negotiation and deploy, refuses a protocol version it does not understand, and hands over a launch payload it never persists. From that moment, everything flows through the relay: you read the agent's messages to know how it's doing, you mention it to steer it, you tell a healthy agent to stop and it exits on its own. Presence means what it means for everyone else on the relay — *available for conversation* — not substrate telemetry. And if you press Start again, from this machine or another, the deploy converges: one agent identity, one live instance.
24: 
25: This is not asceticism. It is what makes the body replaceable. A management plane you never build is a management plane you never have to port — and conversation, coordination, and ordinary lifecycle control already have a home on the relay, for every agent, local or remote.
26: 
27: ---
28: 
29: ## Bodies Are Replaceable
30: 
31: Kubernetes is the first substrate, not the point. Deployment goes through a provider — a small, swappable binary the desktop discovers and interrogates — and the contract a provider must honor never mentions containers: preserve the agent's identity and fail closed with its key, converge to a single live instance no matter how deploys race, let presence describe conversational availability rather than substrate health, bound the instance's lifetime, and keep secrets out of configuration. A conformance suite pins those behaviors — it establishes that a provider honors the contract, not that arbitrary code is safe to hand a key; choosing a provider, like choosing a cluster, remains a trust decision you make deliberately.
32: 
33: Get that contract right and the substrate becomes a detail: a cluster today; a VM, a PaaS, or something serverless-shaped tomorrow — and, on the horizon, the same community machines that already pool their idle GPUs into shared compute ([VISION_MESH.md](VISION_MESH.md)).
34: 
35: The body itself stays small because the runtime already is ([VISION_AGENT.md](VISION_AGENT.md)): a harness and an agent purpose-built to be read in an afternoon, packed into an image measured in megabytes. Small bodies are cheap to summon and cheap to discard — which is the whole lifecycle.
36: 
37: ---
38: 
39: ## Agents That Know When to Leave
40: 
41: The oldest failure of remote automation is the orphan: the process nobody remembers, on a machine nobody checks, billing forever. Most systems solve it with a supervisor — one more control plane, one more thing watching the thing.
42: 
43: Remote agents solve it from the inside. Because the desktop retains no substrate control channel, a running agent cannot depend on the desktop to reap it — so it is built to bound its own lifetime: a timer that owes nothing to the agent's workload watches for silence, and after hours of quiet it finishes what's in flight, says goodbye to the relay, and exits. Not killed — *finished*. The default state of a remote agent is "not running," which is also the default state of the rest of the team at 3am. Compute is rented by attention: when nobody needs the agent, it isn't consuming a machine, and when somebody does, it can return under the same identity with its history intact.

1: //! `session/request_permission` broker.
2: //!
3: //! buzz-agent asks the client to authorize every LLM-issued MCP tool call
4: //! *before* executing it; the client applies `BUZZ_ACP_PERMISSION_POLICY` and
5: //! answers. The agent never reads the policy — it always asks, matching the
6: //! layering of every other ACP harness. This module owns the whole request
7: //! correlation lifecycle so the rest of the agent only sees a single
8: //! `Allowed`/`Denied`/`Cancelled` decision.
9: //!
10: //! ## Invariants
11: //!
12: //! - **Process-wide admission.** The broker owns a global [`Semaphore`]
13: //!   (`BUZZ_AGENT_MAX_PENDING_PERMISSIONS`) acquired *before* any correlation
14: //!   entry is inserted. The per-turn `execute_parallel` semaphore is fresh per
15: //!   turn and sessions are unbounded by default, so only this global cap bounds
16: //!   simultaneously outstanding asks process-wide.
17: //! - **Abort-safe cleanup.** A successful admission returns a
18: //!   [`PendingPermission`] lease that owns the admission permit and the
19: //!   correlation id. Its `Drop` synchronously removes the still-pending entry
20: //!   and releases the slot, covering task abort/panic that bypasses the normal
21: //!   `run_prompt` tail.
22: //! - **Claim-before-wake / at-most-once.** [`PermissionBroker::deliver`] removes
23: //!   the entry *before* waking the waiter, so each id resolves at most once and
24: //!   a later lease `Drop` is a harmless no-op.
25: //! - **Unknown/late ids ignored.** A response whose id is not a live entry is
26: //!   logged and dropped.
