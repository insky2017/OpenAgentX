# FenixAgent 对照研究

## 结论

- **FenixAgent 的企业控制面定位与 OpenAgentX 更接近。** 它实际连接了 Agent 配置、执行环境、持久实例、ACP 引擎、会话以及多种业务入口；不是只有管理页面和协议抽象。角色指令、Skills 与工具配置进入执行环境，是值得参考的核心接线。
- **最值得学的是正式 Chat 的状态与操作反馈。** 当前轮归属、取消确认、审批的一次性处理、登录失败与连接失败分开、会话内任务和文件入口，都能帮助 OpenAgentX 减少用户自行排查内部模块的成本。本批未运行真实浏览器，不能据此宣布整体体验更好。
- **共享执行基础并未使各入口的终态语义一致。** 定时任务、工作流与正式 Chat 对结束、取消、异常和恢复的处理存在差异；工作流对远端孤儿任务的取消标记及有条件重跑，也不能证明外部进程已停止或副作用可安全重试。具体源码与隔离验证见独立报告。
- **功能丰富不等于适合整套迁入。** PostgreSQL、Redis/Yjs、ACP Relay、执行编排、插件及可选的沙盒、网关、知识库、记忆、Sites 各有目标场景；对当前单 owner 的 OpenAgentX，优先补齐日常操作，不新增一套运行状态或企业平台。
- **保留现有 A/B/C 改进顺序。** 借鉴配置真正注入、状态来源明确和失败后可恢复；保留 OpenAgentX 的事务、Mailbox、Journal、lease/fencing 和 query/mutation 效果边界。参考研究不等于这些改进已实现。

## 对现有改进顺序的补充

| 原批次 | FenixAgent 的参考 | OpenAgentX 最小落点与验收 |
|---|---|---|
| A：可靠撤回与当前结果 | 正式 Chat 区分取消请求、取消确认和未确认中断；按当前 turn 防迟到事件串扰 | 修已有取消事务和最新 Run 投影。未执行任务取消后不再启动；活动取消失联保留未知；旧轮回复/停止不覆盖新轮，随后可处理下一任务 |
| B：真正完成与继续 | AgentConfig 编译为实际引擎指令、Skills 与工具配置；持久实例身份和运行代分开 | 用现有 Adapter 确定性注入角色并记录版本，按真实支持能力续上下文；query 回复、mutation 可核效果、Task/Run/Journal 一致。统一 Web/Console/API 的有限结果规则，不能仅复制 stopReason→success |
| C：首次就绪与恢复 | 登录、连接、节点/环境不可用分开；当前会话集中显示待处理、任务与文件；重连按错误原因选择 | 用现有 API 支撑 overview 的就绪、待处理、最近结果和下一步。首次失败恢复不重复提交；陈旧状态有提示；80×24 / 390px 能到结果与继续入口 |

Chat 的 accepted/committed 是命令处理与投影层面的确认，不能提升为模型已经完成或业务副作用已核实。OpenAgentX 可借鉴用户反馈方式，继续由现有持久权威链裁定工作结果。
