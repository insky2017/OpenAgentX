## 结论规则

- “可用”必须说明哪些用户流程在何种环境获得了动态证据；源码存在不自动等于可用。
- 风险按现实触发、用户后果、证据强度、最小改法与验收目标排序；严重程度标签不自动升级为本批实施任务。
- 重构须说明解决哪种重复成本或领域问题；能用局部修复完成的，不建议全盘重写。
- 每份报告自行明确未覆盖项；总报告不把模块结论相加成虚假的“整体验收通过”。
