从一次操作，到可追溯的执行结果

编号为顺序；补充消息、审批与取消走持久控制通道

01 / DISPATCH

选择 Agent，提交任务

Web 或 Console 调用 Control API，携带认证与幂等键。权限通过后才允许创建工作。

02 / COMMIT

原子保存工作与投递

Task、Message、Mailbox 和 Journal 一起提交。返回 Task ID / version，只说明已受理。

03 / CLAIM

Worker 领取持久工作

长轮询 claim；校验 instance、generation、lease 和 fencing，拒绝失效 Worker 的迟到操作。

04 / BEGIN ATTEMPT

固定执行快照，启动 turn

创建 RunAttempt，固定 Adapter、Backend、模型、session 与网络版本。Adapter 启动真实 CLI。

05 / EVENTS + FINISH

回传事件与终态

Runtime 输出作安全投影。Worker 上报 events / finish；领域层分别持久化 Run 结果与 Task outcome。

06 / OBSERVE + WAIT

界面跟随，Worker 继续等待

客户端从一致快照与 cursor 跟随事件。Worker 释放本次执行容量，等待下一项 Task。

三个结果层，不能合并成一个“成功”

控制面受理

queued / task.created

任务已保存。尚未证明 Worker 领取或 Runtime 执行。

→

Runtime / RunAttempt

succeeded + Runtime reply

一次 turn 返回终态与回复。仍需独立判断业务任务结果。

→

Task outcome

uncertain / business_effect_unverified

当前 Runtime 成功但缺少独立副作用证据时的结果；回复仍会保留。

并发控制

steer / approval / cancel → 正式 API → 持久 Mailbox → Worker → Adapter。结束与消息、取消竞态由事务、版本 CAS 和状态规则裁决。

稳定身份、临时执行权与本地凭据

Agent 与 Worker

agent_id 是稳定业务身份。
WorkerInstance / generation 标识当前常驻实例。
lease / fencing 限定其有效执行权。
tmux 名称不进入这条信任链。

Web 与 CLI

Web：Cookie + CSRF + RBAC。
CLI：UDS + 可撤销 Token + scope，绑定 installation。
本地 credential 为 0600；服务端仅保存 Token 摘要。

Secret 与观察数据

网络 Secret 存在独立权限保护文件中：目录 0700、文件 0600。
不声称实现了磁盘加密。
Console / Web 使用安全投影，不展示原始凭据。

ADR-007 · 仍为提案

尚未实现同 Agent 跨 Worker generation 自动继承网络绑定。新 generation 仍须符合当代测试、发布与应用条件，旧回执不能充当成功。

已安装的 Runtime 更新策略

主可执行文件摘要变化可告警继续；Adapter / protocol、wrapper / helper 等其他身份差异仍拒绝。它不等于取消代际 fencing。
