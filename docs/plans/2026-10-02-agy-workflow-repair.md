# OpenAgentX 工作流修复计划：先让 AGY 真正可日用

日期：2026-10-02。状态：**核心工作流已修复、安装并完成本轮真实日用验收**。本计划保留实施前基线；已做/未测逐项见[交付与证据](../reports/validation/2026-10-02-agy-workflow/DELIVERY.md)。具体测试设计见[端到端测试用例](2026-10-02-agy-workflow-e2e.md)，问题背景见[综合评估摘要](../reports/assessment/2026-10-02-summary.md)。

## 要点

- **首个交付目标是完成日常工作。** 添加／导入一个领域 Agent，打开工作台，提问或执行任务，看到正确结果，能够取消、追问、关闭后返回、继续下一项。
- **本轮只围绕 AGY CLI 打通。** 保留 WorkBuddy／仓库中的 CodeBuddy 相关实现，不增加其功能、专项测试或真实模型验收。先支持本机 Linux、当前用户、user-systemd 和现有 AGY 运行环境。
- **用一个本机入口接好 Agent 与服务。** Fleet、Worker YAML、Token、tmux 和网络发布步骤由程序组织；用户只提供名称、工作目录、职责文档，必要时完成一次登录或网络选择。
- **复用已有底座和 ADR-006。** 修断点，不重建调度平台。用户看 Agent、工作和结果；Task、Run、Worker、Runtime 的技术区别留在诊断中。
- **每批修复同时补测试，第一批就打真实链。** 单元测试、故障集成测试、真实 AGY、真实浏览器和安装验收分别记录；不等所有功能开发完再开始 E2E。
- **安全强化按实际影响排队。** 不因完整组织权限、远程部署、强沙箱等未来能力拖延本机试用；现有路径会造成重复执行、数据破坏、凭据泄漏或误报成功的问题仍要做最小修复。

## 2. 用户怎样用：三个日常步骤

**第一次：添加或导入 Agent。** 向导只询问显示名称、工作目录和职责。职责可以选现有 Markdown 文档，也可以输入几句话生成默认文档；高级用户可导入现有定义。程序自动生成或复用 Agent identity、Worker 配置和 Fleet 条目，绑定同一个工作目录，并完成本机服务与网络准备。已有 Agent 应原地纳管，不能重复创建或无提示覆盖配置。

**平时：打开 Agent，直接工作。** 展示明确的“可开始／正在工作／需要处理／已暂停”及原因。会话区显示最新进展、回复和产物。首次缺配置只显示缺少的那一步；不要求用户分别检查 systemd、Worker 心跳和 binding。Web 为主要工作界面，Console 保留为终端入口，两者读取同一结果和就绪规则。

**用完：关闭界面即可。** 后台继续工作；重新打开回到当前任务。需要停止接新工作时选择“暂停”，当前工作结束后后台停止；“恢复”启动新一代 Worker 并重新准备网络。“取消当前工作”与“暂停 Agent”分开，不把暂停描述成冻结模型进程。

候选已实现以下入口；安装与真实验收状态见[执行记录](../reports/validation/2026-10-02-agy-workflow/EXECUTION-LOG.md)：

```text
openagentx agent add             # 向导：新建或导入，准备完成后进入工作台
openagentx agent open <agent>    # 日常打开；未运行时给直接启动/恢复动作
openagentx agent pause <agent>   # 停止接单，当前工作结束后暂停
openagentx agent resume <agent>  # 恢复后台、检查就绪并给出工作台入口
```

向导内部复用现有 `agent apply`、`console login`、`fleet init/up/status/down` 和网络工作流。新增的是单 Agent 增量配置、状态协调和恢复入口。启动本机服务由本机 CLI 完成；Web 不新增通用执行 shell 的接口。显式暂停的 Agent 不因刷新网页自动恢复。

`OAX:overview` 改为小型导航：Agent 就绪原因、待处理工作、最近结果、打开／恢复入口。进入终端不再落在空 shell；不开发统计大屏。

## 3. Domain、Work、Worker、Runtime 怎样结合

| 概念 | 本轮明确的职责 |
|---|---|
| Domain Agent | 一个领域的稳定负责人：身份＋工作目录＋职责输入。复用 AgentIdentity/AgentProfile，不再增加同义 Domain 实体；职责不宣称为操作系统隔离 |
| 工作（Task） | 用户交付的一项请求、等待原因和结果；复用现有 Task，补结果验收及前后工作关联，不另建 WorkItem 状态机 |
| RunAttempt | 一次真实执行尝试，固定工作目录、角色版本、Runtime 参数、截止时间和结果归属；普通用户无需操作它 |
| Worker service | 为该 Agent 常驻接单的后台进程。服务在线不等于 AGY 可执行；关闭窗口不关闭 Worker |
| Runtime | Worker 调用现有 `agy-batch`／`agy-graft` 完成一次执行。保留新会话／恢复会话能力，按实测能力使用，不复制 Holon 的 Provider/tool loop |

本轮采用一个 Agent 对应一个受管 Worker service、同一 Worker 一次执行一个 AGY Run；多个领域共用现有 daemon，不为每个领域再部署一套平台。用户配置的 Agent 身份、工作目录与职责，经同一入口生成服务配置，服务启动后仍以该身份接单。

本轮重点接好四处：

1. **角色确实生效。** 在执行前读取指定职责文档，将内容及摘要纳入本次执行输入；工作目录与 Agent 定义一致。角色更新在下一次执行生效，正在运行的输入不漂移。缺文件时明确提示，不能显示“加载成功”后实际不传。
2. **工作有明确交付。** 问答按 ADR-006 的完整最终回复交付结束；执行任务展示回复、产物和验收状态。query 不代表只读沙箱，也不证明答案正确。界面使用“问答／执行任务”名称，显式传 intent，保留选择；不让模型猜类型，服务端默认值不偷偷改变。
3. **继续有上下文。** 工作完成后的新输入创建关联的新 Task，携带前项目标、选定结果和产物引用。先做有长度上限、来源可查看的上下文继承，不承诺跨 Task 原生 session 自动续接。执行中补充显示“下轮处理”；AGY 只支持 queued steer。明确成功结束且完整回复的 mutation 即便业务效果未独立核验，也可处理用户已提交的下一轮消息，旧 Run 原始结果和未核验事实保留；物理停止不明、回复不完整或取消中不得自动续跑。
4. **长运行可控、恢复不重做。** 复用现有独立 heartbeat/control 和 AGY timeout、进程清理。接通一个可配置的单次运行时限，记录到 Run 并显示截止时间；静默不等于卡死，心跳不延长任务时限。重启后恢复工作记录和观察；旧副作用不确定时不自动重跑，用户仍可处理其他已确认可执行的工作。

**执行任务的最小验收办法：** 当前没有平台业务核验入口。本轮新增绑定 Task＋Run＋结果版本的“接受结果／结果有问题”记录，保存验收人、时间、备注及产物引用，并写入 Journal。正常执行结束后可显示“待验收”，接受后显示“用户已验收”，不强迫用户先验收才能开始下一项。原 Run 和 Task 的保守执行记录不被改写，不将人工接受冒充系统独立核验；停止未确认的任务仍单独显示该事实。文件内容独立核对先用于测试，不开发万能自动验证器。

## 5. 参考项目的机制落在哪里

| 来源 | 本轮采用的方法 | 落点 |
|---|---|---|
| Holon | 稳定领域负责人、可恢复工作记录、明确等待与交付责任 | 用现有 Agent/Task/Journal 表达角色、当前工作、等谁和结果；不复制第二套状态链 |
| Paseo | 完整的发送—过程—结果—继续—停止路径 | 最新结果、关联继续、返回会话、取消反馈 |
| Buzz | 在线、就绪、可控制分开；停止要有回执 | 统一就绪原因；取消请求和实际停止分开呈现 |
| OpenHarness | 输入实际装配，结果绑定本次 attempt，未知投递不盲重发 | 角色/目录/参数快照、结果归属、幂等与重连 |
| Multica / FenixAgent | 配置到执行端的真实接线、按当前轮归集交互 | 角色注入、补充消息去向、错误和恢复提示 |
| Wake / Orca | 历史与继续入口对应准确结果，产物便于查看 | 最近工作、产物来源、继续此工作 |

借鉴基于此前固定版本研究，不代表这些项目的新版本已验收。原报告均可从[综合摘要](../reports/assessment/2026-10-02-summary.md)进入。本轮采用设计方法，暂不移植第三方平台或代码。

## 6. 哪些后置，什么才算交付

后置：完整组织治理、自主跨领域委派、远程 Worker/mTLS 扩展、强沙箱、额外秘密加密体系、全套审批平台、更多 Runtime、完整长期记忆检索、原生移动端及安装外壳。分别在开放多用户、跨机、执行不可信输入或出现明确业务需求时再处理。AGY 当前未实测支持的能力不展示为可用；已有工具执行信任边界保持清楚，不以 query 标签包装成只读保护。

只修会影响本轮日用的实际问题；其它发现登记触发条件和后续动作。角色/路径错误、重复执行、丢输入、错误显示成功、无法取消和无法恢复，是工作流缺陷，不能作为“安全细节”一起延期。

**交付判定：** 本轮 22 组用例逐项有结果，核心 AGY 主链和真实安装链没有失败或未验证项；Agent 创建后不用人工修数据库、改 YAML 或注入 tmux 命令；实际产物正确、下一项可运行、取消及恢复不重复执行；安装来源与已测候选一致。不以测试数量或功能百分比代替这些结果。

下一步按批次 0 接续现有候选，批次 1/2 并行推进；每批输出“现在能做什么、证据在哪里、剩余什么”，最后提供一页日常使用说明。实施与验证分工，委派代理继续使用至少 `gpt-6-astra / high`。

## 2026-10-02 补充：真实执行强证据（必须落实）

用户已授权修复、使用现有开发凭据、候选安装和低副作用真实验收；文档及规则提交后立即执行，无需再次询问是否开始。执行进度记录在 `docs/reports/validation/2026-10-02-agy-workflow/EXECUTION-LOG.md`。

每次真实验收保存独立运行目录和 manifest：用例ID、D/R/I层次、时间、源码commit/工作树状态、运行命令、配置来源、AGY/wrapper/Go/Web版本与哈希。必须留存 daemon、Worker、Runtime 的实际 stdout/stderr 或服务 journal，正式 API 的请求结果与 Task/Run/Message/Journal 快照，浏览器操作/DOM/截图或 PTY 记录，以及文件内容/hash、进程树与停止检查等外部效果证据。仅有结论JSON、截图、exit0、mock或单测日志均不能单独支持真实E2E通过。某种日志确无输出也须保存采集方式和空输出事实，不编造日志。

原始执行资料保留在本机持久证据目录，测试清理不得连带删除；可复核的脱敏副本提交到 `docs/reports/validation/2026-10-02-agy-workflow/evidence/<run-id>/`。密码、Token、Cookie等由现有凭据文件/受控环境直接使用；可用凭据不作为重复授权障碍，明文不进入Git或用户可见日志。脱敏只去秘密，不抹掉命令结果、时间、关联ID和失败原因。manifest记录各证据路径、SHA-256和脱敏说明；提交前检查引用文件真实存在。

失败、超时、工具错误和复验分次保留，禁止覆盖首次失败；只有原始执行与产品状态/外部效果能够互相对应才可记PASS。D层是补充证据，不得替代计划规定的R/I。每次交付链接到具体日志与证据目录，不只声称“已测通过”。
