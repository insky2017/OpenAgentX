# oaxops 与 oaxctl 一次切换

用户已确认纯字母命令 `oaxops`、`oaxctl`，授权入库、安装、在 writer 空闲时迁移原会话及回执、删除旧入口，并提交推送 main。核心 `openagentx` 不改名。

## 本轮结果

- `clients/oaxctl`：标准库单文件 HTTP 客户端，XDG 配置与私有会话，提供登录、查询、派发、追加和等待。
- `scripts/operations/oaxops`：标准库单文件宿主运维入口，工作目录仍为 `/home/sky/docs`，状态迁至 `${XDG_STATE_HOME:-$HOME/.local/state}/oaxops`。
- 新入口直接安装到 `~/.local/bin`，不保留旧命令、软链、包装器或双轨目录。
- 移动原 thread、session、writer 锁、角色及组织交接、事件原始记录。有效历史不删除，不重放已执行或结果未知的事件。

## 验收与证据

1. 实现前确认原 thread、writer 状态和准确 pane；迁移时独占原锁，同一 inode 移至新目录，session 与 events 按 SHA-256 对照。
2. `oaxops status` 返回原 thread；真实 flock 验证互斥和子进程持锁；已有成功、失败、未知回执和异正文 key 的结果正确，重复调用不启动模型。
3. 隔离真实 OAX daemon/API 验证客户端鉴权、CSRF 轮换、任务创建、消息版本和幂等；客户端等待超时不取消或重派。HTTP 契约测试与模型任务执行分开报告。
4. 安装脚本 SHA 与源码一致，原 pane 恢复同 thread，旧入口和旧运行目录不存在。六业务 Worker 与 daemon 不需重启。
5. 更新使用指南、API 文档和当前导航。历史证据的原始内容保持，迁移后的文件定位索引可更新；不将过去的单元名称改写成未实际存在过的新单元。
6. 检查 diff、必要测试、秘密、冻结 ADR 不变，合入并推送 main，核对远端 SHA。

## 范围

不修改 OAX 调度、业务 Agent、业务任务或数据库状态；不扩大为自动自愈系统。新客户端原型来自 `/tmp/oaxctl_staging/`，入库前核对实际服务端契约；不直接携入私人凭据或实例专属 Agent 字典。
